# P04 · 自回归 → 块扩散：模型转换、训练与部署

> **难度** ★★★★★ ｜ **算法 : 系统** 7 : 3 ｜ **建议人数** 2 ｜ **最低硬件** 4–8×80GB（训练）+ 1×80GB（部署） ｜ **基座** 训练：HF / 官方训练代码；部署：SGLang 或 vLLM

## 1. 背景

从零训练一个扩散语言模型代价极高。2025 年下半年起，一条更实用的路线迅速兴起：**把已有的自回归（AR）模型转换成块扩散模型**。

- **Fast-dLLM v2**（ICLR 2026）：只用约 1B token 微调，就把 Qwen2.5-7B-Instruct 转换成块扩散模型，论文报告精度与原模型相当、吞吐提升约 2.5×；
- **SDAR**：AR 与扩散协同的范式，把 AR 模型低成本转换为块扩散模型，发布了 1.7B ~ 30B 的系列模型；
- **LLaDA2.0**：从 AR 模型出发，扩展到 100B MoE 的块扩散模型，并在 SGLang 中实现了推理支持。

这条路线的算法空间很大：块大小怎么选？注意力 mask 怎么设计？训练目标与课程怎么设计？如何保持原 AR 模型的能力？**但是，算法设计必须同时考虑部署**：块大小影响 KV 复用与并行度，attention mask 必须能被高效 kernel 支持，模型结构要能被推理引擎加载。

**本项目要求你完成一次完整的 AR → 块扩散转换**（在小模型上），并把转换后的模型部署到推理引擎中，在质量和真实吞吐两方面评估。

## 2. 论文 → 引擎的鸿沟

| 问题 | 说明 |
|---|---|
| 训练配置与推理配置耦合 | 训练时的块大小、mask 形式决定了推理时能否复用 KV、能用哪个 kernel |
| 模型结构需要引擎支持 | 自定义的 attention mask 或额外模块需要在引擎中实现（out-of-tree 模型 / dLLM 接口） |
| 质量评估需在引擎内完成 | HF 上的精度不代表引擎内精度（解码策略与数值实现不同） |
| "转换后到底快不快" | 需要与原 AR 模型（含投机解码）在同一引擎、多 batch size 下公平对比 |

## 3. 项目目标

1. 以 Qwen3-0.6B / 1.7B（或同级别）为起点，复现一种 AR → 块扩散转换方法（Fast-dLLM v2 或 SDAR 风格）；
2. 研究至少一个关键设计维度（块大小、mask 设计、训练数据量、训练目标）对质量与可部署性的影响；
3. 将转换后的模型部署到 SGLang / vLLM（复用已有的块扩散支持，或通过插件实现），完成正确性验证；
4. 与原 AR 模型在引擎中做多 batch size 的质量-吞吐对比。

## 4. 任务分解

### 4.1 阶段一：转换训练（必做）
- 读懂所选方法的训练细节：attention mask（块内双向、块间因果）、掩码策略、损失函数、互补掩码等技巧；
- 在小模型上完成转换训练（数据可用开源 SFT 数据，规模按算力调整，例如几亿 token）；
- 在 GSM8K、MATH500、HumanEval、MBPP、MMLU 等任务上评测，与原 AR 模型对比。

### 4.2 阶段二：设计维度研究（必做，至少一个维度）
- **块大小**：4 / 8 / 16 / 32 对质量、TPF、推理吞吐的影响；
- **训练数据量**：精度随训练 token 数的变化曲线；
- **mask / 目标设计**：例如是否使用互补掩码、是否在块内保留部分因果结构。

### 4.3 阶段三：部署与对比（必做）
- 将模型转换为引擎可加载的格式（必要时实现 out-of-tree 模型或适配引擎的 dLLM 接口）；
- 正确性：引擎内输出与 HF 实现一致（或精度一致）；
- 在引擎中对比：原 AR 模型、AR + 投机解码、你的块扩散模型，覆盖 batch = 1 ~ 64+。

### 4.4 进阶（加分）
- 用"部署友好"作为约束反过来改进训练：例如为了大 batch 下的吞吐，训练支持更少去噪步数的模型（步数蒸馏 / 一致性训练）；
- 把块扩散模型用作投机解码的草稿器（参考 DFlash 的思路），对比两种用法；
- 扩展到更大的模型（如 7B / 8B）。

## 5. 关键知识点（汇报必须讲清楚）

**算法**
- 掩码扩散语言模型的训练目标（ELBO 推导的基本思路）；
- 块扩散的 attention mask 设计，以及训练时如何高效实现（例如把带噪块与干净上下文拼接）；
- AR → 扩散转换为什么能保留 AR 模型的知识；有哪些能力最容易退化；
- 并行解码的质量损失来源。

**系统**
- 块大小对 KV 复用、并行度和吞吐的影响；
- 训练时的 mask 设计与推理 kernel 的兼容性；
- 引擎中块扩散的执行路径（参考 P03）。

## 6. 实验设计

- **模型**：Qwen3-0.6B / 1.7B（主实验）；
- **任务**：GSM8K、MATH500、HumanEval、MBPP、MMLU；
- **必须产出**：
  1. 转换模型 vs 原 AR 模型的精度对比表；
  2. 所研究设计维度的消融（质量 + TPF + 引擎吞吐）；
  3. 引擎内吞吐 vs batch size（AR / AR + 投机 / 块扩散）；
  4. 训练曲线与训练成本统计。

## 7. 答辩追问示例

1. 推导掩码扩散模型的训练目标，并说明它与 AR 的交叉熵损失有什么联系。
2. 你的训练中块内 attention 是双向的，推理时如何保证 KV 复用的正确性？
3. 块大小从 8 改成 32，训练和推理两侧分别发生了什么变化？
4. 你的模型在哪类任务上退化最严重？为什么？
5. 转换后的模型在 batch=64 时还比原 AR 模型快吗？为什么？

## 8. Agent 使用建议

- 训练脚本、数据处理、评测流水线可以交给 Agent，但 **attention mask 与 loss 的实现必须逐行核对**，并用小例子手算验证；
- 训练前先在极小规模（如几百步）上 sanity check：loss 是否下降、能否过拟合小数据；
- 两人分工建议：一人负责训练与评测，一人负责部署与性能分析。
